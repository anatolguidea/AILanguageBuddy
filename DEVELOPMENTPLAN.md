🚀 Phase 1: Connectivity & Core Chat UI (Timeline: 1 week)
Goal: Ship the full “bridge” between the mobile app and the AI brain with a clean, modern, user-friendly UI.
- Build Chat UI in Flutter (use packages like chat_bubbles or custom bubbles) with light/dark friendly theme.
- HTTP Client integration: configure POST calls to Spring Boot endpoint; centralize base URL/env handling.
- State Management: introduce Provider/Riverpod/Bloc to keep messages across rotations and simplify reuse.
- CORS & IP Config: backend must accept requests from local network IP for on-device testing.

🛠️ Phase 2: Core Learning Features - MVP (Timeline: 3 weeks)
Goal: Make the app a complete AI-driven language tutor, not just chat.
- Supabase Auth: implement login/register in Flutter; pass userId to backend.
- Adaptive Pedagogy: parameterize system prompt by user’s level (A1–C2) and target language; tailor explanations and exercises.
- Corrections UX: visualize corrections with highlights/annotations, not just plain text.
- Conversation History: load and persist chats per user from chat_messages at chat open; add pagination.
- Scenario Mode: curated AI-guided role-play scenarios (travel, restaurant, job interview) with branching dialogue.
- Story Mode: AI-generated short stories with inline comprehension questions and vocabulary highlights.
- Lessons/Tracks: lightweight lessons generated by AI from common user mistakes; include spaced review prompts.

🎮 Phase 3: Gamification & Progression (Timeline: 2 weeks)
Goal: Increase retention through progress mechanics.
- Streaks & XP: compute XP after each correct interaction; store per user.
- User Profile Screen: show level, XP, streak, recent achievements.
- Quests/Challenges: daily and weekly goals (e.g., complete 2 scenarios, learn 10 new words).
- Mini-Lessons from Errors: mine frequent mistakes from DB and auto-create personalized micro-lessons.

🧠 Phase 4: Advanced AI Experiences (Timeline: 2 weeks)
Goal: Deepen immersion and personalization.
- Speaking & Pronunciation: integrate speech-to-text + AI feedback; optional slow playback/phonetics.
- Vocabulary Builder: AI-curated flashcards from chats/stories with spaced repetition scheduling.
- Multi-Model Strategy: use Strategy pattern to swap AI providers (Groq/LLM) per task (chat vs. story vs. feedback).
- Offline Prep: cache lessons/stories and recently used vocabulary for low-connectivity use.

🛡️ Phase 5: Security, QA, and Polish (Timeline: 2 weeks)
Goal: Prepare for demo and store release readiness.
- Clean Architecture: organize Flutter into Data/Domain/Presentation layers; enforce DI on both frontend and backend.
- Repository Pattern: abstract DB so Supabase could be swapped (e.g., MySQL) without changing services.
- Testing: JUnit for backend services/controllers; Flutter widget and integration tests for chat, scenarios, lessons.
- Accessibility & UX polish: modern UI patterns, large touch targets, proper contrast, and responsive layout.
- Documentation: finalize API specs and user guide; record demo flow (Register → Chat → Scenario → Story → Correction → Progress).

💎 Technical Principles to Follow
- Dependency Injection everywhere to keep components decoupled.
- SOLID & Clean Code: short, single-responsibility methods.
- Reusable Code: build custom Flutter widgets (ChatBubble, ScenarioCard, LessonTile, ProgressBadge) and shared theme tokens.
- Strategy Pattern: swap AI models/providers without rewiring business logic.
- Observer/Notifier Pattern: update UI instantly on new AI responses or progress changes.
- Modern, user-friendly UI: clear hierarchy, consistent theming, smooth transitions, and mindful empty/error states.
